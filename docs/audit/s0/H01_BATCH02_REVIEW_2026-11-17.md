## 2. P0 — Region crosswalk is still incomplete

- `H01_region_id_crosswalk.csv` has 81 rows, but **71/81 rows remain** `BLOCKED_UNATTACHED_REGIONS_1836_CSV`.
- Only 10 rows have a non-blocked target; those rows refer to only **9 distinct target region IDs**, because two source slots both point to `DZ_SENEGAMBIA`.
- The crosswalk contains no completed one-to-many destination mapping. The two rows for `SSA_REG_02` and `SSA_REG_03` point to the same target with weights `0.575` and `0.425`; these weights do not sum to 1 for either source slot. The file does not define whether weights are source allocation fractions, target contribution shares, or relative weights.
- `H01_region_facts_RECONCILED.csv` has a column named `repo_region_id_verified`, but its values are statuses such as `verified_from_review_head_cc84a87a`, not repository IDs. The actual `region_key` is still a synthetic slot for most rows.
- `SSA_REG_03` uses `DZ_SENEGAMBIA_PART_B`, which is not an ID in the repository's 662-row region table.
- `SSA_REG_06` maps all 360,000 residents of the reconstructed Grain Coast area to `LIB_MON`, while 356,500 are described as indigenous/rural and only 3,500 as ACS settlers. The repository region `LIB_MON` is specifically `Liberia (Monrovia)`; it is not a whole-country/hinterland identifier. This needs a geographic allocation to the actual map regions, not a single enclave-region binding.
- `SSA_REG_02` and `SSA_REG_03` both map to `DZ_SENEGAMBIA`, although the repository separately has `GBR_GAM` for The Gambia (Bathurst). The Gambia/Bathurst enclave and hinterland/Casamance components need to be separated before aggregation.
- Several clear repository regions are not yet used in the crosswalk, e.g. `ETH_TIG`, `SHE_ANK`, `BUG_BUG`, `OMA_ZAN`, `OMA_SWA`, `DZ_NYAMWEZI`, `GBR_CAP`, `GBR_CAE`, `MER_EAS`. These are examples for re-review, not an instruction to force every H01 slot into a guessed one-to-one match.

**Required repair:** use one row per `(H01 source slot, repository target region ID)` pair. For each H01 source slot, the sum of allocation fractions across all target rows must equal 1. If multiple H01 source slots contribute to one target region, state whether their population components are disjoint and may be added. Produce the final region-fact table by actual repository region ID; leave values missing when evidence or a defensible allocation is absent. Do not make the row count match by inventing IDs.

## 4. P1 — Event data is parseable but not runtime-ready

- The 29 dates parse and intervals are ordered, but **25/29 events still contain** `BLOCKED_SSA_REG_*` in `affected_repo_region_ids`.
- `ALL` and `ALL_REGIONS` appear as special actor/region tokens but are not ordinary IDs in the repository registry/region table. Define a formal supported wildcard convention or replace them with valid IDs/structured scope.
- `TRN` appears as an actor in events beginning 1835, 1837 and 1838; `OFS` appears in the 1835–1838 Great Trek event. The repository registry says these are future entities beginning in 1852 and 1854. They must not be actors before their start dates. Represent the migrating Boers/frontier actors with a historically valid 1836 actor/annotation, or describe the event without an active future-state ID.
- The event for Omani relocation to Zanzibar lists only `DZ_EAFRICA` as actor even though the repository has the playable entity `OMA` and map regions `OMA_ZAN` / `OMA_SWA`; re-evaluate the actor attribution.
- The Great Trek event still uses future-state IDs; Ndebele migration and Blood River also use `TRN` too early.
- Event-region IDs must be derived from the corrected region crosswalk. Do not leave blocked references in an event file intended for engine import.

## 5. P1 — Provenance audit is still not row-complete

The provenance file has 40 records. It covers 17 playable-entity GDP/capita omissions, multiple leader/population claims, and one aggregate claim (`CLM_040`) for all 81 regional population estimates. It does **not** provide one auditable provenance record for each of the 81 region-population rows. Although region facts contain a `source_id` and locator, a single source field is insufficient where the method explicitly combines Manning (2014) with a regional monograph.

Required:
- one provenance record per numeric regional claim and per material entity-profile/military/economy claim;
- all source IDs used in a composite method, not only the main monograph;
- exact page/table/archival locator and method/range for estimates;
- explicit data-quality reason for every missing value;
- bibliography entries for every source ID.

The source register currently has 25 entries. The revised Law/Bay split is accepted at the register level; no source ID mismatch was found in the six uploaded files.
